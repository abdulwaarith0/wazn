Wazn app map وَزْن

A guide to where things live in Wazn. In the app you pour a three-letter Arabic root into a pattern (a wazn), watch the letters fly into place, and collect the word that results.

The main pieces

  • Screenssrc/screens/: Intro, Roots, Workshop, Collection and Quiz. src/App.tsx switches between them.
  • The animationsrc/components/WordAssembly.tsx: letters fly from their tiles into the ف ع ل slots and join into the real word.
  • Arabic textsrc/lib/arabic.ts splits a word into letters with their vowel marks and adds invisible joiners, so each piece keeps its joined shape.
  • Contentsrc/data/: roots, patterns and the reviewed word list (words.ts).
  • Progresssrc/lib/progress.ts holds the rules (collect, unlock, seal), and src/lib/storage.ts saves them to localStorage.
  • Teststests/: joining, word data, progress, labels, quiz and audio file names (Vitest).

One action, end to end: tapping a pattern

Route through the code reference, not toured

  1. The tap: src/screens/Workshop.tsx

    Search for const pick = async. It looks up the word for this root and pattern (wordFor), waits for the animation to finish, then plays any audio and collects the word. Collecting happens after the word lands, so the reward never arrives before the word does.

  2. The flight: src/components/WordAssembly.tsx

    Search for async function fly(. It uses FLIP: measure the tile and the slot, start the flyer on the slot, push it back to the tile with dx/dy, then animate that offset to 0 along an arc. At 72% of the flight the letter cross-fades from its standalone shape to its joined shape. Weak and doubled roots then run transform(): the regular form's changing letters glow and it turns into the real word.

    The flight keyframes 
    x:      [dx, dx * 0.45, 0, 0, 0],
y:      [dy, dy * 0.45 - 46, 0, -4, 0],        // -46 = arc height, -4 = bounce
scaleX: [s0, s0 * 1.35, 1.06, 0.98, 1],        // squash wide on landing...
scaleY: [s0, s0 * 1.35, 0.9, 1.04, 1],         // ...and short, then spring back
times:  [0, 0.5, 0.86, 0.94, 1],               // share of FLIGHT (0.76 s)

  3. Saving: src/hooks/useProgress.ts → src/lib/progress.ts

    Search for collectWord. It runs the pure rule collect() (collecting a word again changes nothing), saves the result, and compares unlocks and seals before and after to tell App which moment to show. Damaged or old saved data starts fresh (parseProgress), and blocked storage falls back to memory (createStore).

A practice to reuse

Prove the riskiest animation by itself, before building around it. The hard part of Wazn was flying separate Arabic letters into slots without breaking how they join. Before any app code existed, a throwaway page (devpost/research/animation-spike.html) proved the FLIP flight and the joiner trick. It became slice 1, and the rest of the app was built around something that already worked. The joining rules then got tests (tests/arabic.test.ts, e.g. كَاتِب + "rprr" → فَاعِل), and the timings live in named constants, so retuning the feel never touches the logic.

For a future project: when one effect carries the whole idea, build it as a standalone spike first, move what can be checked (data, text rules) into tests, and keep the parts you'll tune by feel (durations, distances, easing) as named values in one place.
